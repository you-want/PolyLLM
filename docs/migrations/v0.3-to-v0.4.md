# PolyLLM 0.3 → 0.4 迁移指南

> 配套：`docs/protocol.md`（契约与决策 D1–D9）、`docs/compatibility.md`（能力矩阵）。
> 基线：0.3.0 已发布（npm / PyPI）。本文件只列**需要用户改代码或感知行为变化**的项。

## 保持不变的（无需迁移）

- 9 个公共错误码（`AMBIGUOUS_MODEL` … `UNSUPPORTED_PARAMETER`）语义不变。
- `PolyLLMError.code` 判断路径全部可用；老 `catch (e) { if (e.code === 'PROVIDER_ERROR') }` 继续工作。
- 所有 `UnifiedRequest` / `UnifiedResponse` / `UnifiedStreamChunk` 现有字段名不变。
- 供应商插件导出名、模型清单、wire 构造/解析函数不变。
- 插件可注入 `transport` 构造参数不变。

## 需要改的（破坏性 / 行为变化）

### 1. 读流 delta：Python dict → 属性访问（D4）

Python 流式 `delta` 从宽泛 `dict[str, Any]` 收窄为强类型 `StreamDelta`。

**before（0.3）**
```python
async for chunk in llm.chat_stream(model):
    text = chunk.delta.get("content", "")
```

**after（0.4）**
```python
async for chunk in llm.chat_stream(model):
    text = chunk.delta.content or ""
```

工具参数增量同样：`chunk.delta.tool_calls`（属性，非下标）。

### 2. 能力缺失从静默忽略改为报错（D6）

对 `vision=false` 的模型传 `image_url` 部件、对 `jsonMode=false` 的模型设
`jsonMode=true` 等，0.3 部分插件会静默忽略；0.4 统一抛 `UNSUPPORTED_PARAMETER`
（`details` 含 `capability` 字段）。

**before（0.3）**
```python
# gemini（vision=false）传图片 → 被忽略，按纯文本处理
resp = await llm.chat("gemini:gemini-pro", {"messages": [msg_with_image]})
```

**after（0.4）**
```python
try:
    resp = await llm.chat("gemini:gemini-pro", {"messages": [msg_with_image]})
except PolyLLMError as e:
    if e.code == "UNSUPPORTED_PARAMETER":
        print(e.details["capability"])  # "vision"
```

### 3. usage 缺省归零 + 标记（D5）

供应商未返回 usage 时，`usage` 恒为零值，并在
`providerMetadata.usageUnavailable = true` 标记。0.3 各插件行为不一。

**before（0.3）**
```ts
// 某些插件 usage 可能为 undefined 或部分字段
const total = response.usage?.totalTokens
```

**after（0.4）**
```ts
const total = response.usage.totalTokens          // 恒为 number（缺省 0）
const noUsage = response.providerMetadata?.usageUnavailable === true
```

### 4. 供应商错误细粒度分类（D1，向后兼容）

`PROVIDER_ERROR` 的 `details` 新增 `category` / `retryable` / `requestId` /
`retryAfterSeconds`（§7）。老判断继续可用，新代码可读取分类：

**after（0.4，可选）**
```ts
catch (e) {
  if (e.code === "PROVIDER_ERROR" && e.details?.retryable && e.details?.category === "rate_limited") {
    // 手动退避或走 withRetries
  }
}
```

### 5. 重试：默认关闭，显式开启（D8）

0.4 不改变默认行为（不重试）。需要重试时显式传策略：

**after（0.4，TypeScript）**
```ts
const resp = await llm.chat(model, { messages }, {
  retries: { maxAttempts: 3, baseDelayMs: 500, jitter: 0.25 },
})
```

**after（0.4，Python）**
```python
from polyllm_core import with_retries
result = await with_retries(lambda: plugin.chat(req, cfg, ctx),
                            policy={"maxAttempts": 3}, deadline_ms=ctx.timeout_ms)
```

注意：重试**不保证幂等**——首次响应未到达时供应商可能已计费；Core 不自动执行
tool，收到首个可见流 chunk 后不自动重放。

### 6. 超时语义：整个调用预算（§6.1）

`timeoutMs` / `timeout_ms` 是**总预算**（含重试、退避、流读取），不是单次尝试
预算。升级若你原来假设它是单次超时，请重新核算。Python 侧 0.3 插件内部缺省
120s 不再是公共契约，请显式传 `timeout_ms`。

### 7. 取消资源释放保证（D7）

取消/超时后本端保证释放 reader/连接/timer，不再后台继续请求；但**不保证**
供应商侧停止生成（断连后可能继续生成并计费）。Python 可中止 transport 让
"task 取消 = socket 已关闭"成为可承诺事实（见 `docs/protocol.md` §11.2）。

## 验证

- 官方插件 0.3.0 基础应用 fixture 在 0.4.0 通过 `pnpm verify:protocol` 与
  `verify:stability`（含跨语言 diff）。
- 自定义插件：若直接读 `chunk.delta` 下标或依赖静默能力忽略，按上述第 1、2 项调整。
