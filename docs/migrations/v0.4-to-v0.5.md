# PolyLLM 0.4 → 0.5 迁移指南

> 配套：`docs/protocol.md`（§6.4 模型发现超时）、`docs/compatibility.md`（能力矩阵）。
> 基线：0.4.0 已发布（npm / PyPI）。本文件只列**需要用户改代码或感知行为变化**的项。

## 保持不变的（无需迁移）

- 9 个公共错误码语义不变。
- `chat` / `chatStream` / `chat_stream` 的签名、错误分类、重试策略不变。
- 所有插件导出名、模型清单、wire 构造/解析函数不变。
- `listModels()`（Core 注册表）行为不变。

## 需要感知的（新增能力）

### 1. 模型发现接入统一超时（§6.4 / T3）

0.4.0 中 `listModels` 保持插件自身默认超时（D9 搁置）。0.5.0 起：

- TypeScript：`llm.listProviderModels(provider, { timeoutMs })` —— 模型发现请求受调用预算约束。
- Python：`await llm.list_provider_models(provider, timeout_ms=...)`。
- 不传超时参数时行为与 0.4.0 一致（不做 Core 层预算，transport 仍有 socket 兜底）。

**无需迁移代码**：这是新增公共入口，老调用路径（`llm.listModels()` 返回注册表）完全不变。

### 2. Gemini base64 图片输入（T2，若本版完成）

- `image_url` 部件中 `data:` 前缀（`data:image/png;base64,...`）现在会映射为 Gemini `inlineData`，不再抛 `UNSUPPORTED_PARAMETER`。
- 纯远程 URL（`https://...`）仍抛 `UNSUPPORTED_PARAMETER`（SSRF 边界保持）。
- 媒体类型白名单：`image/png` / `image/jpeg` / `image/webp` / `image/heic` / `image/heif`；单张 ≤ 20 MiB。

**升级代码示例**（0.4.0 显式拒绝的场景现在可用）：

```ts
// 0.4.0: 抛 UNSUPPORTED_PARAMETER
// 0.5.0: 正常调用
await llm.chat('gemini:gemini-2.5-flash', {
  messages: [{
    role: 'user',
    content: [
      { type: 'text', text: '描述这张图' },
      { type: 'image_url', imageUrl: { url: 'data:image/png;base64,...' } },
    ],
  }],
})
```

## 验证

- 自定义插件：若自行实现了 `listModels` / `list_models`，签名为 `listModels(config, context?)` / `list_models(config, context=None)`，context 可选，向后兼容。
- 若依赖 0.4.0 "Gemini 拒绝所有图片" 的行为做断言，更新测试——base64 图片现在会被接受。
