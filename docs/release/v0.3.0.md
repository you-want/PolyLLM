# PolyLLM `v0.3.0`

> 发布版本：0.3.0（仓库冻结后由 npm/PyPI 工作流执行上传）

`v0.3.0` 是 PolyLLM 的生态扩展版本：新增 Gemini 与 Ollama 两个供应商插件（TypeScript + Python 双语言同步）、OpenAI-compatible 预设体系，以及 `polyllm new-plugin` 自定义插件脚手架。

## 新增供应商插件

### Gemini（TypeScript + Python）

- 独立 wire 协议：`generateContent` / `streamGenerateContent`，不依赖 OpenAI-compatible 通道。
- 支持工具调用（`functionDeclarations` / `functionCall`）与流式输出。
- 当前版本显式声明 `vision: false`：统一协议中的远程图片 URL 暂不转换为 Gemini `inlineData`，避免发送无效请求；图片输入留到 0.4.0 评估。
- 初始模型清单：`gemini-2.5-flash`、`gemini-2.5-pro`（带别名、快照与 `createModelSpec` 动态模型）。
- `listModels` 走 Gemini `/models` 接口。

### Ollama（TypeScript + Python）

- 本地默认 Base URL `http://127.0.0.1:11434`，无需 API Key 即可调用与探测。
- `listModels` 走 Ollama 原生 `/api/tags` 接口（列出本地已拉取的模型），而不是 OpenAI 的 `/models`。
- `chat` / `chatStream` 走 Ollama 0.5+ 提供的 OpenAI-compatible `/v1/chat/completions` 端点，复用 openai wire 构造/解析逻辑。
- 初始模型清单：`llama3.1:8b`、`qwen2.5:7b`，并支持 `createModelSpec` 动态模型。

## OpenAI-compatible 预设

在 `@you-want/polyllm-openai-compatible` 内置 `openaiCompatiblePresets`，覆盖：

| 预设 | Base URL | 密钥环境变量 |
| --- | --- | --- |
| OpenRouter | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` |
| 通义千问 (DashScope) | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `DASHSCOPE_API_KEY` |
| Moonshot (Kimi) | `https://api.moonshot.cn/v1` | `MOONSHOT_API_KEY` |
| Groq | `https://api.groq.com/openai/v1` | `GROQ_API_KEY` |
| vLLM（自建） | `http://127.0.0.1:8000/v1` | `VLLM_API_KEY` |
| LiteLLM（自建） | `http://127.0.0.1:4000/v1` | `LITELLM_API_KEY` |

这些供应商不再出独立插件，统一走 OpenAI-compatible 通道。Studio 的 "OpenAI 兼容厂商" 面板新增预设选择器：选中后自动填充 Base URL、密钥环境变量名与默认模型，用户仍可手动覆盖。云端预设带推荐模型清单，本地/自建网关（vLLM/LiteLLM）模型清单留空由用户填写。

## 自定义插件脚手架

新增 `polyllm-cli` 子命令 `new-plugin`：

```bash
npx @you-want/polyllm-cli new-plugin --provider acme --provider-name Acme --dir ./packages/acme
```

生成的包骨架包含：

- `package.json` / `tsconfig.json`：直接对接现有 pnpm workspace 与 `tsconfig.base.json`
- `src/index.ts`：`LLMPlugin` 模板（`createModelSpec` / `listModels` / `chat`，默认走 OpenAI 风格端点，需按供应商 wire 改写）
- `test/plugin.test.ts`：mock `fetch` 的骨架测试
- `README.md`：发布前检查清单（wire 实现、模型清单、mock 集成测试、`pnpm verify:packages`）

生成的模板包可以直接跑 `pnpm verify:packages`，与官方插件走同一套质量门禁。

## Studio 更新

- 供应商目录新增 Gemini 与 Ollama 卡片，支持启用、模型探测与项目生成。
- Studio 供应商注册表收敛为单一来源（`createStudioPluginRegistry`），CLI 发布版服务与开发版服务共用同一份，新增 provider 不再需要改两处。
- Ollama 面板不再强制填写 API Key（本地服务），Base URL 默认 `http://127.0.0.1:11434`；provider 元数据新增 `auth` 字段（`required` / `none`），生成配置、`.env.example` 与 LLM 模块统一据此决定是否写入密钥，Ollama 不写 `apiKeyEnv`。
- "OpenAI 兼容厂商" 面板接入预设选择器（见上）。
- 生成项目依赖版本约束升到 `0.3.0`（npm `^0.3.0`，Python `>=0.3.0,<0.4.0`）。

## 协议与一致性修复

- Gemini（TS + Python）模型发现改走官方 `GET /models`，并对返回的资源名做 `models/` 前缀归一，消除"发现→聊天"双重路径拼接。
- Gemini（TS + Python）流式输出改按官方 `?alt=sse` 协议解析 `data:` 事件，Python 侧同时修正此前"一次性读全响应"造成的伪流式问题，改为逐行增量解析。
- Gemini（TS + Python）图片输入：远程 URL 图片在能力层显式拒绝（`vision` 能力声明为不支持），不再发送无效的 `inlineData` payload；base64/SSRF 防护的远程图片下载留到 0.4.0 评估。
- Ollama（TS）对齐 Python 侧行为：请求合并 `ProviderConfig.headers`，支持带认证的反向代理与企业网关场景。
- Python `create_llm` 在构造阶段将环境变量解析结果写回 provider 配置，client 构造后不再受环境变量变化影响。
- 新增 Gemini / Ollama 的 HTTP 契约集成测试（mock 官方 wire：`GET /models`、SSE 流、NDJSON、`/api/tags`、发现→聊天端到端路径、自定义 header）。
