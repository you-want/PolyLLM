# PolyLLM `v0.5.0`

> 发布版本：0.5.0；npm / PyPI 待发布。

`v0.5.0` 承接 0.4.0 明确延期的 P1 项，补齐能力与发布可靠性：Gemini base64 图片输入、模型发现接入统一超时预算，以及 npm 发布恢复工具。9 个 npm 包与 7 个 Python 包同步到 `0.5.0`。

## Gemini base64 图片输入（T2）

0.4.0 中 Gemini `vision=false`，`image_url` 部件统一抛 `UNSUPPORTED_PARAMETER`。本版开放 base64 路径：

- `image_url` 中 `data:image/<mime>;base64,...` 映射为 Gemini `inlineData`（`mimeType` + `data`）。
- 媒体类型白名单：`image/png` / `image/jpeg` / `image/webp` / `image/heic` / `image/heif`；单张上限 20 MiB。超限或不支持类型抛 `UNSUPPORTED_PARAMETER`，`details.parameter` 指明原因。
- **远程 URL（`http(s)://`）仍拒绝**——SSRF 边界保持，不引入自动下载。
- 已验证的 Gemini 模型（`gemini-2.5-flash` / `gemini-2.5-pro`）在 `specs`/`models` 中翻为 `vision=true`；动态模型 `createModelSpec` 同样 `vision=true`。

详见 [能力矩阵](../compatibility.md) Gemini 行与 [迁移指南](../migrations/v0.4-to-v0.5.md)。

## 模型发现统一超时（T3）

0.4.0 D9 把 `listModels` 排除在统一超时外（保持插件自身默认）。本版把它纳入 §6.1 调用预算语义：

```ts
// TypeScript
const models = await llm.listProviderModels('openai', { timeoutMs: 15_000 })
```

```python
# Python
models = await llm.list_provider_models("openai", timeout_ms=15_000)
```

- 不传超时时行为与 0.4.0 一致（不做 Core 层预算，transport 仍有 socket 兜底）。
- 模型发现是单次请求，无重试/退避参与；超时分类为 `category: "timeout"`。
- 6 类官方插件的 `listModels` / `list_models` 均接收并应用该选项；Studio 模型发现端点传入 15s 预算。

详见 [protocol.md §6.4](../protocol.md)。

## npm 发布恢复工具（T1）

0.4.0 发布实测暴露：registry 503 导致部分包失败，且 changesets 把部分 503 误报进成功列表，只能全量重跑靠 skip 补传。`scripts/promote-npm-dist-tag.mjs` 重写：

- **标签预检**：移动前逐包确认目标版本在 registry，缺失报 `missing-version` 且不动标签。
- **部分成功清单**：结束输出逐包状态（`ok` / `already-set` / `missing-version` / `error`）+ 成功/失败计数，失败退出非零。
- **有限重试**：5xx/503 指数退避最多 3 次；403/409 不重试直接报告。
- **幂等可重跑**：已正确的标签标 `already-set` 跳过，重跑只补缺失。`--dry-run` 预演不动标签。

`promote-latest` 工作流操作现调用此脚本；[发布手册 §7/§9](../release.md) 恢复规则相应更新。
