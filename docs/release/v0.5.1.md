# PolyLLM `v0.5.1`

> 发布版本：0.5.1；npm / PyPI 已完成发布（2026-10-25）。

`v0.5.1` 是兼容性修订版：修复 0.5.0 已确认的请求映射与跨语言差异，让首次接入和能力说明可信。9 个 npm 包与 7 个 Python 包同步到 `0.5.1`。本版无需要用户改代码的公共接口变化。

## Gemini 请求结构修复（T1）

0.5.0 把生成参数（`temperature`、`topP`、`maxOutputTokens`）错误放在请求根部。本版修复为官方 `generationConfig` 子对象，TS 与 Python 两端同步；只有存在生成参数时才输出该对象。

- `contents`、`systemInstruction`、`tools`、0.5.0 新增的 `inlineData` 位置保持不变。
- 独立预期依据：[Google 官方 wire 转换](https://github.com/googleapis/python-genai/blob/main/google/genai/models.py) 与 [GenerateContent API](https://ai.google.dev/api/generate-content)，避免两端实现互相证明同一错误。
- 测试同时断言正确子对象与根部不存在错误字段；Studio 的 `maxTokens: 1` 探测请求也覆盖。

## 参数策略跨语言一致（T2）

修正 Python 在非 strict 策略下"保留不支持的 tools、却警告已忽略"的矛盾行为，两端统一：

- 不支持 tools 的模型：`strict` 抛出稳定错误（行为不变）；`auto` / `lenient` 产生明确 warning 并**清空**请求中的 tools（Python 此前错误地保留）。
- 支持该能力时两端保留原工具定义，行为不变。
- 策略分支加入共享协议 runner（`param-policy.json` 样例 + 变异检查）；回归断言检查最终 wire，"警告忽略但仍发送"的变异被拒绝。
- 修订 [protocol.md §5](../protocol.md) 中与实现相反的策略描述。现有公共错误码与默认策略不变；数字参数的 auto 钳制 / lenient 越界取最小值等既有行为先如实记录，重新定义另立次版本，不夹带进本次。

## 能力证据与首次接入（T3）

- 能力矩阵 Gemini 图片说明与 0.5.0 实现同步，区分 Mock 验证与真实服务验证；不再把已实现能力列为未来需求。
- 解释 OpenAI-compatible 默认保守能力声明与 strict 本地拒绝边界；未知能力不宣传为上游明确不支持，也不全设 `true` 绕过校验。
- 能力矩阵增加可追溯记录字段（能力、provider/model、版本、测试模式、日期、证据路径、限制）。
- README 与 `examples/published/` 入口逐条实测：泛站点／模板地址改为可运行入口；外部平台限制写出实际步骤与本地替代路径。

## 验收与已知限制

- 定向回归与共享契约：`pnpm verify:protocol`（40 用例 + 10 变异）通过，0 跨语言差异；`pnpm verify:stability`、`pnpm test:scripts` 通过。
- 真实 Gemini canary（`maxTokens: 1`）：**未执行**——无授权凭据，明确记录，不伪造通过。
- CodeSandbox / StackBlitz 首次运行：外部平台限制未实测，README 已提供可运行入口与本地替代路径。
